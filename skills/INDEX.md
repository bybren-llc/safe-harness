# Skills index

One line per skill folder under `skills/`. Canonical bodies stay in each `SKILL.md`. Do not fork them.

- `acceptance-criteria` — [`acceptance-criteria/SKILL.md`](acceptance-criteria/SKILL.md) — Shape acceptance criteria, definition of done, and a demo script when a bolt lacks clarity. Use before construction when AC is missing or untestable. Defer O2 scope to the HITL owner.
- `adr-madr` — [`adr-madr/SKILL.md`](adr-madr/SKILL.md) — Write one Architecture Decision Record per decision in MADR 4.0 with a Confirmation section, and update the decision log. Use when locking a structural, options, or execute decision.
- `api-contract-check` — [`api-contract-check/SKILL.md`](api-contract-check/SKILL.md) — Run contract tests and breaking-change diffs on an adopter's OpenAPI spec. Warn-only first. Use when the adopter has a spec path configured. Skip cleanly when none exists.
- `board-sweep` — [`board-sweep/SKILL.md`](board-sweep/SKILL.md) — Scheduled read-only sweep of queues, PRs, and stalls. The only write is board-row status. Use on the adopter's sweep cadence. Never decide, post, or merge.
- `bolt-lifecycle` — [`bolt-lifecycle/SKILL.md`](bolt-lifecycle/SKILL.md) — Run one bolt from brief through implement, evidence, QAS, RTE, and merge request. Use for a bounded unit of work on Low, Med, or High paths. Not for open-ended research or constitution edits without a brief.
- `concur-queue` — [`concur-queue/SKILL.md`](concur-queue/SKILL.md) — Maintain the queue of items waiting on HITL concur — exact head, tier, why, QAS/RTE status. Ping only when ready. Use when a pack needs the HITL owner's own words.
- `cve-watch` — [`cve-watch/SKILL.md`](cve-watch/SKILL.md) — Run a scheduled dependency and CVE scan, count severities, dedupe, and file one tracking issue in the owning repo. Scanner not fixer. Use on the watch cadence or when SecEng asks for a scan.
- `decision-pack` — [`decision-pack/SKILL.md`](decision-pack/SKILL.md) — Assemble the constitution/03 decision-pack minimum for a Med or High change. Use when a bolt needs human approve / change-request / escalate at an exact head.
- `delegation-brief` — [`delegation-brief/SKILL.md`](delegation-brief/SKILL.md) — Write a cloud or sub-agent brief with scope, files, tier, stop rules, and evidence to return. Use when handing a bolt to an implementer or a nested agent.
- `doc-drift` — [`doc-drift/SKILL.md`](doc-drift/SKILL.md) — Detect and repair drift between governance docs, README, AGENTS.md, and skills after a merge. Use after a governance or adapter change, or when a later CI drift check warns.
- `env-promotion` — [`env-promotion/SKILL.md`](env-promotion/SKILL.md) — Apply the template default for environments — trunk merge rules, staging auto-promote, prod human gate for prod-risk, deploy freeze during demos. Use when promoting a change across environments.
- `git-advanced` — [`git-advanced/SKILL.md`](git-advanced/SKILL.md) — Merge main to update feature branches, bisect, cherry-pick, and conflict resolution. Use on feature branches. Trunk is main. Never force-push shared branches.
- `github-conventions` — [`github-conventions/SKILL.md`](github-conventions/SKILL.md) — Apply trunk GitHub conventions — branch names, plain commit subjects, Refs/Req trailers, and the PR Requirements line. Use when starting a branch, committing, or opening a PR.
- `hitl-concur-check` — [`hitl-concur-check/SKILL.md`](hitl-concur-check/SKILL.md) — Verify the HITL owner's own words, timestamp, and exact head before any consequential action. Use before merge, tag, secret use, public post, O2 construction, or any relayed "they said yes." An agent relaying approval is never approval.
- `intent-spec-assist` — [`intent-spec-assist/SKILL.md`](intent-spec-assist/SKILL.md) — Help the human owner draft intent.md and spec.md. Propose only. Agents never write those files as done and never merge them. Use when Studio is preparing design text for the HITL owner.
- `lane-routing` — [`lane-routing/SKILL.md`](lane-routing/SKILL.md) — Route work by the delegation map and refuse out-of-lane work. Use when picking up an issue, escalating, or deciding which seat owns a request.
- `link-health` — [`link-health/SKILL.md`](link-health/SKILL.md) — Run blocking in-repo link checks and a weekly non-blocking cross-system scan. Register-first, no invented links, link-rot label. Use when checking a PR's links or running the scheduled scan.
- `ops-rollup` — [`ops-rollup/SKILL.md`](ops-rollup/SKILL.md) — Produce status digests and rolls — queued work, gate waits, weekly trace and gap review. Use for Ops cadence. Output stays internal unless the HITL owner OKs a post.
- `orchestration-patterns` — [`orchestration-patterns/SKILL.md`](orchestration-patterns/SKILL.md) — Run long-running, multi-step agent work with evidence-based delivery and a choice between parallel sessions and subagents. Use when one session cannot finish the bolt.
- `pattern-discovery` — [`pattern-discovery/SKILL.md`](pattern-discovery/SKILL.md) — Check the adopter's existing pattern library before writing new code. Use before new API, UI, storage, or test work in a product repo.
- `portable-evidence` — [`portable-evidence/SKILL.md`](portable-evidence/SKILL.md) — Record a portable evidence row (evidence_id, runtime, exact_head, issue, actor, gate, req_ids) that any runtime can read. Use whenever a gate needs proof.
- `pre-pr-validation` — [`pre-pr-validation/SKILL.md`](pre-pr-validation/SKILL.md) — Run the repo's documented local checks, link check, and trace check before opening a PR, and paste the literal output as evidence. Use immediately before gh pr create or equivalent.
- `privacy-boundary` — [`privacy-boundary/SKILL.md`](privacy-boundary/SKILL.md) — Enforce the personal-boundary rule — no personal-store content, story IP, or private-store facts in repos. Use when drafting, reviewing, or scanning a diff for privacy leakage.
- `qas-review` — [`qas-review/SKILL.md`](qas-review/SKILL.md) — Independent QAS review at the exact head with a QAS: APPROVE or QAS: CHANGES NEEDED verdict. Use when a change is ready for the independence gate. Never review your own implementation.
- `release-notes-and-tag` — [`release-notes-and-tag/SKILL.md`](release-notes-and-tag/SKILL.md) — Draft release notes from the decision pack, REQs, and evidence, plus a CHANGELOG entry. Use when a release is being prepared. Do not publish a tag unless the named executor is doing it.
- `requirements-trace` — [`requirements-trace/SKILL.md`](requirements-trace/SKILL.md) — Add or update REQ-<CMP>-NNN rows and trace-map states (Placed, Deferred, Dropped, Missing). Use when deriving success criteria from spec or intent. Never edit human-owned intent.md or spec.md.
- `research-brief` — [`research-brief/SKILL.md`](research-brief/SKILL.md) — Write a research brief with evidence sources and UNKNOWN markers for a decision pack or Studio handoff. Use when Scout or Studio is gathering, not deciding.
- `retro` — [`retro/SKILL.md`](retro/SKILL.md) — Run a wave or bolt retro against the value set named up front (examples/round-table/metrics.md is an example set). Use at bolt or wave exit. Empiricism retires losing defaults.
- `review-response` — [`review-response/SKILL.md`](review-response/SKILL.md) — Read AI-review and QAS findings yourself, disposition each item, and freeze the head after QAS APPROVE. Use when a review arrives on your PR. Do not push after APPROVE unless Delivery explicitly asks.
- `role-model-card` — [`role-model-card/SKILL.md`](role-model-card/SKILL.md) — Publish and keep a role-to-model-tier card per adapter. Use when adding an adapter or changing defaults. A single maximum-capability model is not the default. Do not run Light-only on O2 construction.
- `rollback-rehearsal` — [`rollback-rehearsal/SKILL.md`](rollback-rehearsal/SKILL.md) — Treat rollback as first-class — rehearse before high-risk deploys, keep a one-step revert, record evidence. Use before a High or prod-risk promotion and when a deploy goes bad.
- `rte-release-gate` — [`rte-release-gate/SKILL.md`](rte-release-gate/SKILL.md) — Run the per-PR RTE PASS/HOLD checklist at the exact head. Use when Delivery sends a ready-for-release packet. Verifies evidence; does not re-review code.
- `seceng-review` — [`seceng-review/SKILL.md`](seceng-review/SKILL.md) — Security, privacy-boundary, and secrets review with negative authority. Use on Med/High/O2 and on any diff that touches auth, secrets, deploy, or privacy. Scanner not fixer.
- `signals-digest` — [`signals-digest/SKILL.md`](signals-digest/SKILL.md) — Research or learning-signals digest from read-only sources, with citations. Use for Librarian cadence. Never write to external platforms.
- `stack-and-model-check` — [`stack-and-model-check/SKILL.md`](stack-and-model-check/SKILL.md) — Research-only tool, model, and price fit check with a ranked recommendation and sources. Use when Scout is asked what to use. No vendor model versions in the output body.
- `start-end-work` — [`start-end-work/SKILL.md`](start-end-work/SKILL.md) — Start a work session (pick issue, branch, read brief) and end it (evidence posted, status, handoff). Use at session boundaries on Delivery work.
- `studio-handoff` — [`studio-handoff/SKILL.md`](studio-handoff/SKILL.md) — Emit or accept the Studio to Delivery handoff artifact (AC, sources, privacy class, exit evidence). Use when spine B knowledge becomes buildable on spine A.
- `testing-evidence` — [`testing-evidence/SKILL.md`](testing-evidence/SKILL.md) — Give the agent a feedback loop — failing test first for bugs, paste literal output as evidence, never weaken a test during a fix. Use while implementing or while QAS is checking evidence.
